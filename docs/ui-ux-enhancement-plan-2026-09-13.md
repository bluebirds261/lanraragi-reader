日期：2026-09-13

APP 定位：LANraragi 服务器的专属阅读器 + 强大完善的云端/本地阅读器；元数据刮削与 EhTagTranslation 翻译匹配是一级刚需（元数据既作档案标签也供搜索匹配）；E-Hentai 账号侧功能（收藏夹同步）移除。

## 〇、现状诊断摘要（决定了本方案的方向）

**做得好的（保留并放大）**
- 液态玻璃设计语言已成体系：主壳底栏（kyant backdrop `MainScreen.kt:1126-1212`）、库页浮动搜索框（`LibraryScreen.kt:1559-1617`）、详情页整页玻璃体系（`DetailScreen.kt:1184-1655`）。
- 三态组件统一（`ui/components/StateViews.kt` 的 Loading/Error/EmptyBox，EmptyBox 支持动作按钮）。
- 封面卡片信息密度好：缓存/固定/收藏角标 + "新"标 + 底部阅读进度条（`ArchiveCard.kt:309-467`）。
- 阅读器沉浸度高：无顶栏、点按呼出底部时间线、10 秒自动隐藏（`ReaderScreen.kt:1141-1291`）。

**问题（本方案要解决的）**
1. **主题不对称**：暗色是定制深黑+蓝紫体系，亮色 scheme 只覆写 2 项、基本是 M3 默认紫（`ui/theme/Theme.kt:32-35`）；无 Typography、无动态色。
2. **组件双轨**：Material `AppTopBar`（二级页）与自绘玻璃顶栏（库页）并存；`components/FloatingActionBar.kt` 是无引用死代码，而真正的详情 FAB（`LiquidGlassVisual`）不读设置里的"悬浮按钮颜色"。
3. **巨型文件**：MainScreen 3065 行 / DetailScreen 3339 行 / LibraryScreen 2829 行 / SettingsScreen 2262 行，可复用组件多为 private，改 UI 成本高。
4. **阅读器短板**：无翻页动画、双击缩放无动画（跳变）、缩放>1 时横滑被完全阻断无回弹、单页加载失败无重试 UI、续读静默跳页无提示、背景色等设置只在设置页有入口、`TankReaderScreen.kt` 是无缩放无 chrome 的二等阅读器（双阅读器并存）。
5. **导航层级偏深**：历史/分类/统计等入口藏在"导航页"（`NavigationScreen.kt`），底栏只有 3 tab + 1 动作。
   （**已解决**：导航页并入设置页的「浏览」组、文件已删除，见 2.1 节修订说明。）

## 一、设计系统层：先统一地基（所有后续工作的前提）

### 1.1 补全主题（`ui/theme/Theme.kt`）
- 亮色 scheme 按 `Accent 0xFF7E8BE0` 派生全套（primary/secondary/tertiary/background/surface/surfaceVariant/outline/error），保持与暗色同族观感；当前只有 2 项覆盖必须重写。
- 新增 `Typography`：标题用 medium 字重收紧行高，正文默认；可选自定义字体入口（设置→外观→字体，默认跟随系统）。
- 可选 Material You 动态色开关（`dynamicDarkColorScheme/dynamicLightColorScheme`，API 31+），关闭时用定制色板——该应用有强烈自定义色文化（底栏色/FAB 色/标签色已有），动态色作为开关而非默认。

### 1.2 玻璃组件库化（新建 `ui/components/glass/`）
把散落三处的玻璃实现抽成四个公开组件，删除 `FloatingActionBar.kt` 死代码：
- `LiquidGlassBar`（横向胶囊条，含 Badge 槽位）← 源自 `MainScreen.kt:1126-1212`
- `LiquidGlassSearchBar` ← 源自 `LibraryScreen.kt:1559-1617`
- `LiquidGlassButton`（icon-only / icon+label）← 源自 `DetailScreen.kt:1558-1655`，**读取 `settings.floatingButtonColor`**（修复当前设置不生效的缺陷）
- `LiquidGlassFab`（大号阅读入口）

### 1.3 顶栏策略统一
新建 `GlassTopBar`（浮动玻璃胶囊：返回 + 标题 + 右侧动作槽），逐步替换二级页的 `AppTopBar`；库页自绘顶栏改用同组件。好处：一处改动全局生效（本方案后续的"顶栏骰子按钮""清空 New"都挂在这个槽位上）。

### 1.4 组件出仓（降低巨型文件耦合，属重构不属新功能）
按批从大文件抽 private 组件到 `ui/components/`：`SegmentedControl`（DownloadScreen:755）、`HistoryRow`、`StatCard`、设置行控件（SwitchRow/DropdownRow/CountRow → `ui/components/settings/`）。不改变行为，只搬家，每批独立可验证。

- **运行时门禁 UI**：`storageRoot` 为空的兜底——下载/离线缓存/原档导出入口被拦截时跳转向导 Step2（设置可单步进入）；SAF 授权被系统回收或存储不可用 → 横幅 + 重新选择 CTA，下载自动暂停（错误类并入 C3"存储不可用"）。

### 3.1 「续读 / 随机」共用抽屉（第 4 键呼出）
点击底栏第 4 键弹出 ModalBottomSheet（复用现有"正在阅读"sheet 容器 `MainScreen.kt:2824-2871`）：

```
│ └─────┘ └─────┘ └─────┘                │
└────────────────────────────────────────┘
```
- 顶部胶囊区域内两个按键：「续读」「随机」，**均为三本**，单选切换，切换时内容区交叉淡入。
- **续读**：最近 3 个阅读会话（数据源为现有阅读历史），卡片显示封面 + 进度条 + "第 N 页"，点击直达 `reader/{arcid}?page=N`。
- **随机**：`GET /search/random?count=3`（A1），**随机范围继承库页当前生效的筛选规则**：
  - 首页未应用任何筛选 → 在全部档案里随机取 3 本；
  - 库页键入搜索/应用筛选后再点随机 → 在符合该搜索与筛选规则的档案里随机取 3 本；
  - 规则映射：分类 → `category`，搜索词与标签筛选 → `filter`（服务端语法），「仅新 / 未标记」（及 A2 落地后的「隐藏读完」）→ `newonly / untaggedonly / hidecompleted`；排序与视图设置不参与随机；
  - 命中不足 3 本时**全部展示**（服务端语义：结果不足时全量返回）；请求失败显示 EmptyBox 重试。
- 随机上下文取库页当前筛选状态（库页筛选 state / `FilterBus`）；从其他 tab 打开抽屉时沿用库页最近一次生效的规则。卡片点击直接进阅读器；右上 ↻ 换一批（同一上下文重新请求）。
- 抽屉内不放其他动作；"查看全部"入口移除（历史走第 3 键导航页 → 历史）。
  （**第五轮修订**：历史入口现为「设置 → 浏览 → 历史」。）
